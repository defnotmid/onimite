# 3D: `view3d{}` in three.js's terms

`view3d{}` draws a 3D scene into a box, described the way three.js describes one: a camera,
lights, meshes (a geometry and a material), glTF, 3MF, OBJ and USD models, particles and
labels. The box composites like any
layer: it is transparent where nothing is drawn, takes `opacity`, and the groups around it
transform, clip, mask and blend it. Whatever you know about three.js carries over; the
differences are listed below. It renders on the GPU, or on the CPU with `--software` (the
same picture).

```lua
video { width = 1280, height = 720, fps = 30, duration = 6, background = "#101218", render = function(f)
  local a = animate(f, { { start = 0, stop = 6, from = 0, to = 2 * math.pi / 3, easing = ease_in_out } })
  view3d {                                            -- the box: x, y, w, h (default: the whole video)
    camera = { type = "PerspectiveCamera", fov = 40,  -- three.js's PerspectiveCamera
      position = { 7 * math.sin(a), 3, 7 * math.cos(a) }, target = { 0, 0.5, 0 } },
    lights = {
      { type = "HemisphereLight", color = "#dbe6ff", ground_color = "#3b3034", intensity = 1 },
      { type = "DirectionalLight", color = "#ffffff", intensity = 2.5, position = { 4, 7, 3 },
        cast_shadow = true, shadow = { map_size = 1024, height = 9, bias = -0.0005 } },
    },
    meshes = {
      { geometry = { type = "PlaneGeometry", width = 10, height = 10 }, rotation = { -math.pi / 2, 0, 0 },
        material = { color = "#c9c2b6", roughness = 0.9 }, receive_shadow = true },
      { geometry = { type = "BoxGeometry", width = 1, height = 1, depth = 1 },
        position = { 0, 0.5, 0 }, rotation = { 0, f.seconds, 0 },
        material = { type = "MeshStandardMaterial", color = "#ff5a4d", roughness = 0.4 },
        cast_shadow = true, receive_shadow = true },
    },
  }
  text { "Title over 3D", x = 64, y = 96, font = "DM Sans", size = 48, fill = "#fff" }
end }
```

## What maps one to one

Every table takes its three.js object's properties in snake case (`groundColor` is
`ground_color`, `castShadow` `cast_shadow`, `widthSegments` `width_segments`), and `type` is
the three.js class name (three.js's own `.type`). A key nothing reads warns
(`unused_field`, with the closest name), in nested tables too, and so does a property the
type does not have (`ground_color` on a `PointLight`).

| three.js | `view3d{}` |
| --- | --- |
| `new PerspectiveCamera(fov, aspect, near, far)`, `camera.position`, `camera.lookAt(t)`, `camera.up` | `camera = { type = "PerspectiveCamera", fov = 50, near = 0.1, far = 2000, position = {x, y, z}, target = {x, y, z}, up = {0, 1, 0} }` (the defaults; the aspect is the box's). Depth is precise to about distance² / (near x 16 million) units: a scene from metres to a planet thousands away (far 40000) needs a near plane as far out as the camera allows (20 for a camera 100+ units from everything), or thin layers flicker |
| `AmbientLight(color, intensity)` | `{ type = "AmbientLight", color, intensity }` |
| `HemisphereLight(skyColor, groundColor, intensity)` | `{ type = "HemisphereLight", color, ground_color, intensity }` |
| `DirectionalLight(color, intensity)`, `.position`, `.target.position`, `.castShadow`, `.shadow` | `{ type = "DirectionalLight", color, intensity, position = {0, 1, 0}, target = {0, 0, 0}, cast_shadow, shadow = {...} }` |
| `PointLight(color, intensity, distance, decay)` | `{ type = "PointLight", color, intensity, position, distance = 0, decay = 2 }` |
| `SpotLight(color, intensity, distance, angle, penumbra, decay)` | `{ type = "SpotLight", color, intensity, position = {0, 1, 0}, target = {0, 0, 0}, distance = 0, angle = math.pi / 3, penumbra = 0, decay = 2, cast_shadow, shadow = {...} }` |

On the mesh, `side_material` paints the walls and bevels (three.js's `[caps, sides]` materials) |
| `TubeGeometry(new CatmullRomCurve3(points), ..., radius, radialSegments, closed)` | `{ type = "TubeGeometry", points = { { x, y, z }, ... }, radius = 0.08, radial_segments = 12, closed = false }`: a lit tube through the points as given (no curve fitting: pass as many as the curve needs), rebuilt each frame so the points can move |

| `scene.environment`, `scene.environmentIntensity` | `environment = "sky.jpg", environment_intensity = 1` (an equirectangular image; a Radiance `.hdr` keeps light past white, so a sun and metal reflections don't clip) |
| `scene.background`, `.backgroundIntensity`, `.backgroundBlurriness` | `background = "sky.jpg", background_intensity = 1, background_blurriness = 0` |
| `renderer.toneMapping`, `renderer.toneMappingExposure` | `tone_mapping = "none"` (`"none"`, `"linear"`, `"reinhard"`, `"cineon"`, `"aces_filmic"`, `"agx"`, `"neutral"`), `tone_mapping_exposure = 1` |
| `new Fog(color, near, far)` / `new FogExp2(color, density)` | `fog = { type = "Fog", color = "#fff", near = 1, far = 1000 }` or `fog = { type = "FogExp2", color = "#fff", density = 0.00025 }` |
| `GLTFLoader` + `AnimationMixer` | `models = { { src = "robot.glb", animation = "Walk", time = f.seconds, morphs = {...}, material = {...} } }` (below) |

Conventions are three.js's: right-handed, Y up, the camera looking down -Z; rotations are
Euler angles in **radians**, applied X, then Y, then Z (onimite's 2D `rotate` is in degrees:
not here); colours are sRGB (`"#ff8800"`, any CSS colour, `rgb()`, or three.js's
`0xff8800`), lighting is linear, the output sRGB (`tone_mapping = "none"` by default, or
`"aces_filmic"`, `"agx"`, `"neutral"`, `"reinhard"`, `"cineon"`, `"linear"` with
`tone_mapping_exposure`). Light units are three.js's physical ones: a white `DirectionalLight` of
intensity 1 lights a white surface facing it to 1/π of white, so scenes use 2 to 3; a
`PointLight` or `SpotLight` with the default `decay = 2` falls off with the square of the distance, so it
needs more (5 to 20 a few units away). Metal (`metalness = 1`) shows only what it reflects:
give the scene an `environment`, or it is dark.

### Outlines in 3D

An outline is 1 unit per outline unit with y flipped, so text reads upright: make it at the
size you want in units (`outline { "A", font = "Bebas Neue", size = 1.5, align = "center",
baseline = "middle" }` is a letter 1.5 units tall, about the origin), or at pixel size with
the mesh's `scale`. Built once per outline and options; move it with `position`,
`rotation` and `scale`.

```lua
local A = outline { "A", font = "Bebas Neue", size = 1.5, align = "center", baseline = "middle" }
meshes[#meshes + 1] = {
  geometry = { type = "ExtrudeGeometry", shape = A, depth = 0.3, bevel_thickness = 0.05,
    bevel_size = 0.03, bevel_offset = -0.03, crease_angle = math.pi / 4 },
  material = { color = "#fffaf0" }, side_material = { color = "#1c1b1f" },
}
```

- `bevel_offset = -bevel_size` keeps the solid's outline the outline's own (as big as
  `path{}` draws it: a 2D shape can turn into its solid without a jump).
- An inward bevel must stay under half of the outline's thinnest part (a stroke, a pixel of
  pixel art, a gap): deeper, that part folds inside out (`extrude_folded`). A 32-pixel mark
  1.5 units wide has 0.047-unit pixels: `bevel_size = 0.012` at most.
- A 2D page into 3D without a jump (`examples/graph_paper`'s Lift): a camera straight on with
  1 unit = 100 px at depth 0, each solid sunk so its front face is on the page, a 3D layer
  fading in under the 2D shapes, then those dissolving.
## What differs

- **No retained scene graph.** There is no `scene.add`: each frame's `view3d{}` lists
  everything in it. Nest transforms with `groups = {...}` (three.js's `Group`) and parent
  onto a model's node with `attach` ("Parts, groups and attaching" below); compute the rest
  in Lua and animate with `animate`, `spring`, `f.seconds` like any value. A model keeps its
  own node hierarchy.
- **Sizes change through `scale`, never through primitive geometry parameters.** Each distinct set
  of primitive geometry parameters (`BoxGeometry`, `SphereGeometry`, ...) makes a mesh that is kept for the whole render (as three.js keeps a
  geometry until you dispose of it). `radius = 1 + f.seconds` makes a new sphere every frame
  and `inspect` reports `geometry_growth`. Keep the geometry fixed and animate the mesh:
  `geometry = { type = "SphereGeometry", radius = 1 }, scale = 1 + f.seconds`. A box that
  grows taller: a unit box with `scale = { 1, h, 1 }` and `position = { 0, h / 2, 0 }`.
  (`LineGeometry`, `LineSegmentsGeometry` and `PointsGeometry` are built per frame in the
  scene, so animating their `points` every frame is free and never causes `geometry_growth`.)
- **Shadows** support up to 4 shadow-casting `DirectionalLight`s and `SpotLight`s
  (the first 4 lights with `cast_shadow = true`; there is no `renderer.shadowMap.enabled`),
  PCF-filtered. For a `DirectionalLight`, the shadow camera is a square orthographic view from
  the light's `position` toward its `target`: `shadow = { map_size = 512, height = 10,
  near = 0.5, far = 500, bias = 0, normal_bias = 0 }` (`height` is `top - bottom`, and
  `left`/`right` follow). For a `SpotLight`, the shadow camera is a perspective frustum from
  `position` toward `target` with field of view `2 * angle` and `far` defaulting to the light's
  `distance` (or `500` when `distance = 0`). A slightly negative `bias` (-0.0005) or a small
  `normal_bias` (0.02) removes acne. Meshes need `cast_shadow` / `receive_shadow` as in
  three.js; `alpha_test > 0` (and glTF `MASK`) cuts out shadows by texture alpha.
- **The camera's aspect** is the box's. `OrthographicCamera` takes the view's `height` in
  world units (`camera = { type = "OrthographicCamera", height = 4, position, target }`);
  its width follows the aspect (no `left`/`right`/`top`/`bottom`, no `zoom`).
- **Video maps**: a clip of the media by file name in a material's map (`map = "clip.mp4"`, a TV
  screen or a cube's faces) plays on the view's clock from its start, looping, at its own size,
  sampled without mipmaps; GPU renders only (`--software` draws the material's colour and
  warns: `view3d_video_software`). Not as `environment` or `background`.
- **Textures** (`map`, `normal_map`, `roughness_map`, `metalness_map`, `emissive_map`,
  `ao_map`; `environment`, `background`) are images of the
  media by file name, sRGB, repeating, with mipmaps; `roughness_map` reads green,
  `metalness_map` blue and `ao_map` red, as glTF packs them. On `meshes` there are no texture transforms
  (`repeat`, `offset`) or second uv set (glTF models import both `TEXCOORD_1` and
  `KHR_texture_transform`). An environment is an equirectangular image (2:1): any image of
  the media, a Radiance `.hdr` keeping light past white. Its lighting maps are made once, the
  first time an image is used as an `environment` (or a blurred `background`).
- **`background`** is an equirectangular image only; for a plain colour leave it out and
  draw a `rect` (or a gradient) under the `view3d`: the box is transparent where nothing is
  drawn.
- **Transparency**: `transparent = true` with `opacity` under 1 blends, drawn after the
  opaque meshes, farthest first, without writing depth (three.js's order); `blending =
  "additive"` adds instead (any order), on any material, ShaderMaterials included (their
  `gl_FragColor.a` scales what they add).
- Not here: other materials (Phong, Lambert, Physical), rect-area lights,
  point-light omnidirectional shadow cubes, post-processing other than `bloom` (2D shader
  passes over the layer do the rest: shaders.md, with the layer's depth through `depth_of`).

## Camera paths and vectors

Plain Lua in the standard library, on `{ x, y, z }` lists (what positions are):

- `vec3_add(a, b)`, `vec3_sub(a, b)`, `vec3_scale(a, s)`, `vec3_lerp(a, b, t)`, `vec3_cross(a, b)`,
  `vec3_normalize(a)` give a new list; `vec3_dot(a, b)`, `vec3_length(a)`, `vec3_distance(a, b)` a
  number. Use them for offsets, look-at points and spacing instead of writing the arithmetic out.
- `path_at(points, t, opts)`: the point a fraction `t` (0..1) of the way along a smooth curve
  through `points` (centripetal Catmull-Rom: it passes through every point, without loops or
  cusps where points bunch up), at an even speed whatever the spacing of the points.
  `opts = { closed = true }` joins the last point back to the first and wraps `t` (an orbit or a
  loop); `easing = ease_in_out` (any easing `ease()` takes, springs included) reshapes `t` so
  the move starts and settles gently. `t` past the ends of an open path stays at its ends.
- `path_tangent(points, t, opts)`: the unit direction of travel there.

```lua
local P = { { 6, 2, 0 }, { 0, 3, 6 }, { -6, 1.5, 0 }, { 0, 4, -6 } }
local t = f.seconds / 8
camera = { fov = 45, position = path_at(P, t, { closed = true, easing = ease_in_out }),
  target = { 0, 0.5, 0 } }                                   -- an orbit that eases in and out
-- or look ahead along the path, like a flythrough:
-- target = path_at(P, t + 0.02)   or   target = vec3_add(path_at(P, t), path_tangent(P, t))
```

## Lines, points, wireframe and instancing (Manim-style 3D)

`LineGeometry`, `LineSegmentsGeometry`, `PointsGeometry`, `wireframe = true` and `instances`
let a script draw 3D axes, grids, vector fields, parametric curves that grow over time,
wireframe polyhedra and large instanced lattices without per-frame geometry allocation:

```lua
video { width = 1280, height = 720, fps = 30, duration = 4, background = "#0b0f19", render = function(f)
  local curve = {}
  local n = math.max(2, math.floor(120 * (f.seconds / 4)))
  for i = 1, n do
    local t = (i - 1) / 119 * 4 * math.pi
    curve[i] = { 1.8 * math.cos(t), -1.2 + 2.4 * ((i - 1) / 119), 1.8 * math.sin(t) }
  end
  local dots = {}
  for ix = -2, 2 do
    for iz = -2, 2 do
      dots[#dots + 1] = {
        position = { ix * 0.9, -1.2, iz * 0.9 },
        scale = 0.08,
        color = ix == 0 and iz == 0 and "#facc15" or "#475569",
      }
    end
  end
  view3d {
    tone_mapping = "agx",
    fog = { type = "FogExp2", color = "#0b0f19", density = 0.06 },
    camera = { position = { 4.2, 2.6, 5.2 }, target = { 0, 0, 0 }, fov = 40 },
    lights = {
      { type = "AmbientLight", intensity = 0.6 },
      { type = "SpotLight", intensity = 30, position = { 3, 6, 4 }, angle = math.pi / 4, penumbra = 0.3 },
    },
    meshes = {
      -- A 3D curve built per frame (no geometry_growth):
      { geometry = { type = "LineGeometry", points = curve, closed = false },
        material = { type = "LineBasicMaterial", color = "#38bdf8", linewidth = 0.04 } },
      -- Coordinate axes as disjoint segment pairs:
      { geometry = { type = "LineSegmentsGeometry", points = {
          { -2.5, -1.2, 0 }, { 2.5, -1.2, 0 },
          { 0, -1.2, -2.5 }, { 0, -1.2, 2.5 },
        } },
        material = { color = "#94a3b8", linewidth = 0.02 } },
      -- A wireframe sphere at the origin:
      { geometry = { type = "SphereGeometry", radius = 0.9, width_segments = 16, height_segments = 10 },
        material = { type = "MeshBasicMaterial", color = "#f472b6", wireframe = true, wireframe_linewidth = 0.015 } },
      -- Instanced spheres on the floor grid, each with its own transform and colour:
      { geometry = { type = "SphereGeometry", radius = 1, width_segments = 12, height_segments = 8 },
        material = { color = "#ffffff", roughness = 0.4 },
        instances = dots },
    },
  }
end }
```

- **Lines and points**: `LineGeometry` connects `points` in order (`closed = true` joins the
  last to the first); `LineSegmentsGeometry` draws each pair `(points[1]..points[2],
  points[3]..points[4], ...)`; `PointsGeometry` draws a square at each point. `points` can be
  a list of `{x, y, z}` tables or a flat `{x1, y1, z1, ...}` number list. `colors` gives
  each point a colour (and opacity): a gradient along a line, segments of their own colours,
  stars of many brightnesses in one mesh; as many as the points (else a Lua error).
- **Linewidth and point size**: `linewidth` (on `LineBasicMaterial`) and `size` (on
  `PointsMaterial`) are in world units when `size_attenuation = true` (the default, scaling
  with perspective distance) or in NDC screen height fraction when `size_attenuation = false`.
- **Wireframe or vertex points on any surface geometry**: set `wireframe = true` (with
  optional `wireframe_linewidth`) or `type = "LineBasicMaterial"` on a `BoxGeometry`,
  `SphereGeometry`, `TorusGeometry`, ... to draw its unique triangle edges as ribbons, or
  `type = "PointsMaterial"` to draw its vertices as points.
- **Instancing (`instances`)**: `instances = { { position = {x, y, z}, rotation = {rx, ry, rz},
  scale = s, color = "#rrggbb" }, ... }` on any mesh draws one instance per entry, composing
  the mesh's own transform with each instance's transform and multiplying `material.color` by
  the instance's `color` when set. An instance can be placed with `from` / `to` (and
  `stretch`) or `look_at` like a mesh: rungs between two strands, links of a chain. A
  ShaderMaterial reads the instance's colour and index as `instanceColor` and `instanceId`.

## ShaderMaterial

`type = "ShaderMaterial"` runs a custom GLSL ES vertex and fragment shader pair on a mesh
(or on every mesh of a glTF model via its `material` override), compiled once per distinct
source pair by `oksl` to SPIR-V/MSL for the GPU and to bytecode for `--software`:

```lua
view3d {
  camera = { position = { 0, 1.2, 4 }, target = { 0, 0, 0 }, fov = 40 },
  meshes = {
    { geometry = { type = "SphereGeometry", radius = 0.9, width_segments = 48, height_segments = 24 },
      material = {
        type = "ShaderMaterial",
        vertex_shader = [[
          varying vec3 vNormal;
          varying vec2 vUv;
          uniform float uTime;
          uniform float uAmount;
          void main() {
            vNormal = normalize(normalMatrix * normal);
            vUv = uv;
            vec3 p = position + normal * (uAmount * sin(uTime * 3.0 + position.y * 5.0));
            gl_Position = projectionMatrix * modelViewMatrix * vec4(p, 1.0);
          }
        ]],
        fragment_shader = [[
          varying vec3 vNormal;
          varying vec2 vUv;
          uniform vec3 uColor;
          void main() {
            float l = 0.3 + 0.7 * max(dot(normalize(vNormal), normalize(vec3(0.4, 0.8, 1.0))), 0.0);
            gl_FragColor = vec4(uColor * l + vec3(vUv * 0.12, 0.0), 1.0);
          }
        ]],
        uniforms = { uTime = f.seconds, uColor = "#ff00aa", uAmount = 0.08 },
        transparent = false,
        side = "front",
        glsl3 = false,
      } },
  },
}
```

- **Dialect**: three.js's GLSL 1 style (`attribute`, `varying`, `gl_FragColor`) by default;
  `glsl3 = true` selects GLSL ES 3.0 (`in` / `out`, declaring your own fragment `out vec4`,
  as in three.js's `glslVersion: THREE.GLSL3`).
- **Built-in uniforms** (declared automatically in the prelude; do not redeclare them):
  - Vertex stage: `mat4 modelMatrix`, `mat4 modelViewMatrix`, `mat4 projectionMatrix`,
    `mat4 viewMatrix`, `mat3 normalMatrix` (of `modelViewMatrix`, as in three.js),
    `vec3 cameraPosition`, `bool isOrthographic`.
  - Fragment stage: `mat4 viewMatrix`, `vec3 cameraPosition`, `bool isOrthographic`.
  - Both stages: `vec3 instanceColor` (the instance's `color`, white without one) and `float
    instanceId` (0, 1, 2, ... in `instances` order; 0 on a mesh without instances): one mesh
    of many instances styles each one, with no mesh per colour.
- **Built-in vertex attributes** (declared automatically in the vertex stage):
  `vec3 position`, `vec3 normal`, `vec2 uv`. On a morphed or skinned glTF model, `position`
  and `normal` are already morphed and posed by the skeleton before `vertex_shader` runs.
- **Uniforms**: `uniforms = { ... }` values are converted each frame: numbers (`float` /
  `int`), booleans (`bool`), tables of numbers (`vec2`, `vec3`, `vec4`, matrices column by
  column, arrays), and colours (`"#rrggbb"`, `rgb(...)`, `0xff8800`) as **linear** `vec3` or
  `vec4`. A string naming a media image (`map = "earth.jpg"`) binds that image to the
  `uniform sampler2D` of the same name (repeating, with mipmaps; `texture2D(map, vUv)`).
- **Depth range `0..1` vs WebGL**: `projectionMatrix` maps `near..far` to `0..w` in clip
  space (Vulkan and Metal's `0..1` NDC depth, not WebGL's `-1..1`). Standard
  `gl_Position = projectionMatrix * modelViewMatrix * vec4(position, 1.0);` works unchanged;
  shaders that construct clip-space `z` directly should write `0..w`.
- **Output, transparency and side**: the fragment colour is written as-is (no sRGB
  conversion, as in three.js's `ShaderMaterial`). `transparent = true` blends the draw in the
  transparent pass; `side` is `"front"`, `"back"` or `"double"`. A mesh with
  `cast_shadow = true` casts shadows from its geometry (without running `vertex_shader`, as
  three.js's default depth material does); `ShaderMaterial` does not receive shadows.

## glTF, 3MF, OBJ and USD models

`.glb`, `.gltf`, `.3mf`, `.obj`, `.usdz` and binary `.usdc` files in `media/` load with the media (a
`.gltf`'s `.bin` and images beside it; a file linked in by a symlink counts as its target). USD reads
its meshes with their materials (UsdPreviewSurface), transforms and units; references to
other files, skeletons, lights and cameras are not read, and what is not read or drawn is
named in `model_warning`. A glTF model draws its default scene in its node hierarchy, with its morph targets,
skins, punctual lights (`KHR_lights_punctual`: directional, point and spot lights transformed
by their nodes) and materials (metallic-roughness, base colour, normal, emissive,
metallic-roughness and ambient-occlusion `occlusionTexture` maps, `TEXCOORD_0` and
`TEXCOORD_1` selected per texture by `texCoord`, `OPAQUE`, `MASK` with `alphaCutoff` —
including cut-out shadows — and `BLEND`, double-sided, plus `KHR_materials_unlit`,
`KHR_materials_emissive_strength`, `KHR_texture_transform` and `KHR_mesh_quantization`). A
`.3mf` (3D Manufacturing Format) archive loads its root model (`_rels/.rels` or
`3D/3dmodel.model`) and any production-extension sub-models into the same `Model` tables,
converting 3MF's Z-up coordinates and 3x4 `<component>` / `<item>` transforms into three.js's
Y-up space, scaling sub-models into the root model's `unit`, and importing `<basematerials>`
(`displaycolor`), `<m:colorgroup>` (`color`), `<m:pbmetallicdisplayproperties>`
(`metallicness`, `roughness`) and `<m:texture2d>` + `<m:texture2dgroup>`. A Wavefront `.obj`
loads its `o` / `g` groups as nodes (faces of any size, `usemtl` splitting meshes by material)
and its `mtllib` `.mtl` beside it: `Kd` colour, `Ke` emissive, `Pr`/`Pm` roughness and
metalness (else from `Ns`), `d`/`Tr` opacity, and `map_Kd`, `map_Ke`, `map_Bump`, `map_Pr`,
`map_Pm` textures. 3MF and OBJ faces without normals get smooth normals within a 60° crease;
sharper edges stay hard. Any model can be drawn with a `material` table overriding every
mesh of the model, `toon = true` (MeshToonMaterial's banded light on its own materials) and
an `outline_width` / `outline_color` cartoon outline:

```lua
view3d {
  camera = { position = { 0, 1.5, 4 }, target = { 0, 1, 0 } },
  lights = { { type = "HemisphereLight", color = "#ffffff", ground_color = "#444444", intensity = 2.5 } },
  models = {
    { src = "robot.glb", position = { 0, 0, 0 }, rotation = { 0, math.pi / 4, 0 }, scale = 1,
      animation = "Walk",       -- a clip by name, or its index (0 is the first); none: the rest pose
      time = f.seconds,         -- seconds into the clip (the default: the frame's, scene-relative)
      loop = true,              -- false holds the last pose
      morphs = { ... },         -- optional: morph target weight overrides by name or 1-based index (below)
      material = { ... },       -- optional: overrides every mesh of the model (standard, basic, toon or ShaderMaterial)
      toon = false,             -- true: cel-shaded bands on the model's own materials
      outline_width = 0,        -- > 0: an outline this thick (world units), outline_color = "#000"
      cast_shadow = true, receive_shadow = false,
      name = "robot",           -- optional: what `attach.model` may call it
      nodes = { Head = { rotation = { 0, 0.4, 0 } }, Cape = { hidden = true } },          -- parts by node name
      materials = { Glass = { cast_shadow = false, material = { color = "#88ccff" } } } }, -- parts by material
    { src = "part.3mf", position = { 1.5, 0, 0 }, scale = 0.01 },
    { src = "chair.obj", position = { -1.5, 0, 0 }, toon = true, outline_width = 0.02 },
  },
}
```

- `show video.lua media` lists the models, `show video.lua media/robot.glb` one model's
  meshes, nodes, `node_names` and `material_names` (what `nodes` and `materials` take),
  animations (`["Walk (1.250s)", "Run (0.800s)"]`: the names `animation` takes), morph
  target names (`morphs`) and `warnings` (what o3d could not read or draw); a file that does not load is
  `undecodable_media` (naming the extension when `extensionsRequired` or `requiredextensions`
  lists an unsupported one), a `src` the media lacks `missing_model`, an unknown `animation`
  `missing_animation` (the model draws in its rest pose), and an unknown morph target
  `missing_morph_target`.
- Not imported: glTF morph target `TANGENT` deltas, cameras in the file, mesh/texture compression
  (`KHR_draco_mesh_compression`, `EXT_meshopt_compression`, `KHR_texture_basisu`,
  `EXT_texture_webp`), `EXT_mesh_gpu_instancing`, and PBR material extensions
  (`KHR_materials_clearcoat`, `KHR_materials_transmission`, `KHR_materials_ior`,
  `KHR_materials_volume`, `KHR_materials_specular`, `KHR_materials_sheen`,
  `KHR_materials_iridescence`, `KHR_materials_anisotropy`,
  `KHR_materials_pbrSpecularGlossiness`), or 3MF Slice/Beam/Volumetric extensions. A material
  extension that is not read draws without it and is named in `model_warning`; an
  unsupported entry in `extensionsRequired` / `requiredextensions` fails to decode
  (`undecodable_media`).

### Parts, groups and attaching

- **Parts by name** (one file, no splitting): a model's `nodes = { Name = {...} }` changes a
  node and everything under it: `hidden`, `cast_shadow` / `receive_shadow` (true adds,
  false takes away) and its own `position`, `rotation` (radians), `scale`, replacing the
  file's (and its animation's) for that node, so wheels turn and doors open.
  `materials = { Name = {...} }` changes every primitive of a file material: `hidden`, the
  shadow flags, or `material = {...}` drawn in its place. Names are as in the file
  (`show video.lua media/<model>` lists them; `model_info` too); an unknown one is
  `missing_model_part`.
- **Attaching**: `attach = { model = 1, node = "Wheel_L" }` on a mesh, model or particle
  emitter places it on that node of the view's model (its number in `models`, from 1:
  the top-level ones, then the groups' in order; or `model = "robot"`, a model's `name`),
  as the node is posed this frame (animation and `nodes` included); its own `position`,
  `rotation`, `scale` are then in the node's space. A model attaches only to one drawn
  before it (`attach_target` otherwise).
- **On a physics body**: `attach = { sim = sim, body = "ship" }` (a `physics3d{}` result and
  a body's name or number) places a mesh, model, emitter or label on that body as it is at
  the view's time, in the space of the groups around it (a group can place a whole
  simulation in the scene). Particles can also be left behind by it (`world_space`).
- **Groups**: `groups = { { position, rotation, scale, attach, meshes = {...}, models =
  {...}, particles = {...}, labels = {...}, lensflares = {...}, groups = {...} } }` places what is in it by its transform, on
  its parent group's; a group's `attach` holds for what in it has none of its own.

```lua
view3d { camera = cam, lights = lights,
  models = { { src = "rover.glb", name = "rover", position = { x, 0, 0 },
    nodes = { Wheel_L = { rotation = { spin, 0, 0 } }, Wheel_R = { rotation = { spin, 0, 0 } } } } },
  meshes = { { geometry = { type = "SphereGeometry", radius = 0.05 }, attach = { model = "rover", node = "Mast" },
    position = { 0, 0.3, 0 }, material = { type = "MeshBasicMaterial", color = "#f00" } } },
  groups = { { position = { 0, 2, 0 }, rotation = { 0, f.seconds, 0 },
    meshes = { { geometry = { type = "BoxGeometry" } } },
    groups = { { position = { 1.5, 0, 0 }, meshes = { { geometry = { type = "SphereGeometry", radius = 0.2 } } } } } } },
}
```

- **Model info at load or per frame**: `model_info("rover.glb")` gives `min`, `max`, `size`,
  `center` (its rest-pose box, in its own units), `nodes` and `materials` (names),
  `animations` (`{ name, duration }`) and `morphs`; nil when the media lacks it.
- **Where a point shows**: `view3d_project(camera, { x, y, z }, { width = W, height = H })`
  (the size defaults to the video's) gives `x`, `y` (pixels from the view's top left),
  `depth` (0 near .. 1 far) and `in_front`, for 2D overlays on 3D points. It does not know
  what hides the point (labels and lens flares below do).

### Labels on 3D points

```lua
labels = { { at = { 0, 2.1, 0 }, w = 220, h = 56, depth_offset = 0.05, attach = {...},
  draw = function()
    rect { x = 0, y = 0, w = 220, h = 56, rx = 10, fill = "#0b0d12", opacity = 0.85 }
    text { "Booster", x = 110, y = 36, align = "center", font = "DM Sans", size = 26, fill = "#fff" }
  end } }
```

A label's `draw` lays out 2D nodes in a `w x h` panel (its own units from the top left). The
panel shows with its bottom centre on the 3D point `at` (in groups and with `attach` like a
mesh), at its size in pixels whatever the distance, and is hidden pixel by pixel wherever the
scene is nearer: behind a hull, and through a net's gaps only. `depth_offset` (world units)
pulls it toward the camera without moving it on screen, so a label on a surface shows (0.02-0.1
for a label pinned to a part). For a point's screen position alone, `view3d_project`.

### Lens flares

```lua
local function glow(size, color)
  return function()
    circle { cx = size / 2, cy = size / 2, r = size / 2, fill = radial_gradient {
      cx = size / 2, cy = size / 2, r = size / 2, stops = { { 0, color }, { 1, "#00000000" } } } }
  end
end
lensflares = { { position = sun, occlusion_radius = 8, attach = {...}, elements = {
  { size = 600, distance = 0, draw = glow(600, rgba(255, 220, 180, 0.8)) },   -- on the sun
  { size = 60, distance = 0.5, draw = glow(60, rgba(120, 170, 255, 0.25)) },  -- a ghost
  { size = 120, distance = 1, draw = glow(120, rgba(160, 140, 255, 0.12)) },  -- mirrored
} } }
```

three.js's `Lensflare`: each element's `draw` lays out 2D nodes in a `size x size` panel
(pixels), shown centred `distance` of the way from the point `position` to its mirror through
the view's centre (0: on the point, 0.5: the centre, 1: mirrored), added to what is behind,
over everything. The whole flare fades by how much of a disc of `occlusion_radius` pixels
around the point is hidden by the scene (a hull or a planet passing in front dims it, then
puts it out) or off the view; behind the camera it is out. A sun at infinity: put
`position` far along its direction from the camera, inside `camera.far`
(`vec3_add(camera.position, vec3_scale(sun_dir, far * 0.5))`); if the sun is also a mesh,
put `position` on its near surface, or the mesh hides its own centre. In groups and with
`attach` like a label. Draw the sun's disc itself in 2D under the `view3d` (the scene hides
it) or as a mesh.

### Particles

```lua
particles = { { rate = 60, lifetime = 1.4, seed = 7, position = { 0, 0.1, 0 }, spread = 0.05,
  velocity = { 0, 2, 0 }, velocity_spread = { 0.5, 0.3, 0.5 }, gravity = { 0, -2, 0 },
  size = 0.12, size_end = 0.35, color = "#ffd080", color_end = "#ff4020", opacity = 1, opacity_end = 0,
  spin = 0, map = "puff.png", additive = true, softness = 0, size_attenuation = true, attach = {...},
  start = 0, stop = 3.5, bursts = { { t = 2, count = 40 } }, world_space = false } }
```

Camera-facing sprites (`map`: a media image, its alpha the shape) from a deterministic
emitter: one is born every 1/`rate` seconds and lives `lifetime` seconds, its place, spread
and turn drawn from `seed` and its own number, so any frame shows the same particles
however it is reached (`time` = the emitter's clock, default the frame's). Each starts within
`spread` (half sizes, or one number) of `position`, moves at `velocity` give or take
`velocity_spread` under `gravity`, and goes from `size`, `color`, `opacity` to their `_end`
over its life, turning `spin` radians a second. `additive = true` adds light (fire, sparks);
blended otherwise, farthest first. `softness` (world units) fades them where they meet
geometry; `size_attenuation = false` makes `size` pixels. Unlit. In `groups` and with
`attach` they move with what they are on (puffs born on a moving hull move with it).

- **Switching on and off**: births run from `start` until `stop` (the emitter's clock;
  default always), and `bursts = { { t, count }, ... }` adds `count` at once at `t` (a puff, a
  blast; `rate = 0` for bursts alone). Particles already born live out their `lifetime`,
  so a stopped jet trails off instead of vanishing (Unity's duration and bursts, three.quarks).
- **Left behind**: on a physics body (`attach = { sim = sim, body = "ship" }`),
  `world_space = true` places each particle by the body as it was when the particle was born
  and gives it the body's velocity then, so exhaust, smoke and sparks stay behind a ship
  that turns or speeds up (three.quarks' `worldSpace`, Unity's World simulation space);
  `gravity` is then the view's. It needs a body: only a body's earlier poses are known
  (a node's pose exists for this frame only).

### Morph targets (blend shapes)

Meshes with morph targets (`POSITION` and `NORMAL` deltas, default `weights`, and
`extras.targetNames`) start at the mesh's default weights, are animated by `"weights"`
channels in the active `animation` clip (`STEP`, `LINEAR`, `CUBICSPLINE`), and can be
overridden per frame with `morphs` — by target name or by 1-based target index (after
three.js's `morphTargetDictionary` / `morphTargetInfluences`):

```lua
video { width = 1280, height = 720, fps = 30, duration = 4, background = "#0f172a", render = function(f)
  local blink = animate(f, {
    { start = 1.0, stop = 1.12, from = 0, to = 1, easing = ease_out },
    { start = 1.12, stop = 1.28, from = 1, to = 0, easing = ease_in },
  })
  view3d {
    camera = { position = { 0, 0.2, 3.2 }, target = { 0, 0, 0 }, fov = 35 },
    lights = {
      { type = "HemisphereLight", color = "#e2e8f0", ground_color = "#1e293b", intensity = 1.2 },
      { type = "DirectionalLight", color = "#ffffff", intensity = 2.5, position = { 2, 4, 3 } },
    },
    models = {
      { src = "face.glb",
        animation = "Talk", time = f.seconds,
        morphs = { Smile = 0.8, Blink = blink },   -- or { [1] = 0.5 } by 1-based index
      },
    },
  }
end }
```

- Overrides in `morphs` apply **after** the clip's animated weights, so a script can play a
  body or speech clip while driving expressions (`Blink`, `Smile`) from `animate` or audio
  cues, or pose morph targets without any `animation`.
- Morphs are applied before skinning (`morph`, then `skin`) in the main pass, the shadow
  pass and `ShaderMaterial` vertex shaders.
- `onimite show video.lua media/face.glb` lists the model's `morphs` target names; an
  unknown target name or out-of-range index reports `missing_morph_target`.

## Physics in 3D (physics3d{})

`physics3d{}` is `physics{}` (api.md) in 3D: rigid bodies simulated by Box3D once, at load,
returned as plain data and sampled per frame. Units are view3d's: metres, +Y up, rotations
Euler XYZ in radians. Call it inside `shared` so a render simulates it once:

```lua
local sim = shared("drop3d", function()
  return physics3d {
    duration = 4,                -- seconds simulated (required)
    gravity = 9.81,              -- m/s² down, or { gx, gy, gz }
    bodies = {
      { static = true, box = { 10, 0.2, 10 }, position = { 0, -0.1, 0 } },             -- the floor
      { name = "cube", box = 1, position = { 0, 4, 0 }, rotation = { 0.3, 0.5, 0 }, bounce = 0.4 },
      { name = "ball", sphere = 0.4, position = { -2.5, 3.5, 0 } },
      { name = "duck", hull = "duck.glb", scale = 0.5, position = { 2, 3, 0 } },       -- a model's convex hull
    },
    joints = { { "rope", b = "ball", from = { 0, 3.5, 0 } } },                         -- no `a`: hung from the world
    kicks = { { t = 2, body = "cube", velocity = { 0, 4, 0 }, spin = { 0, 6, 0 } } },
  }
end)

scene { "Drop", duration = 4, render = function(f)
  local pos, rot = physics3d_at(sim, "cube", f.seconds)      -- { x, y, z }, { rx, ry, rz }
  view3d {
    camera = { position = { 0, 3, 9 }, target = { 0, 1.5, 0 } },
    lights = { { type = "HemisphereLight", intensity = 1 },
               { type = "DirectionalLight", position = { 3, 6, 2 }, intensity = 2.5 } },
    meshes = {
      { geometry = { type = "BoxGeometry", width = 10, height = 0.2, depth = 10 }, position = { 0, -0.1, 0 } },
      { geometry = { type = "BoxGeometry" }, position = pos, rotation = rot,
        material = { color = "#38bdf8" } },
      { geometry = { type = "SphereGeometry", radius = 0.4 }, material = { color = "#f472b6" },
        instances = physics3d_instances(sim, f.seconds, { "ball" }) },   -- { { position, rotation }, ... }
    },
    models = { { src = "duck.glb", scale = 0.5, position = physics3d_at(sim, "duck", f.seconds) } },
  }
end }
```

- Options: `duration`, `gravity` (9.81), `rate` (60 steps a second), `hit_speed` (1 m/s: the
  slowest impact that counts as a contact), `bounds` (the world's box, default ±50 m on each
  axis: `{ min = { x, y, z }, max = { x, y, z } }` or `{ x = { lo, hi }, y = ..., z = ... }`;
  `false`: none), `bodies`, `joints`, `kicks`, `thrusts`.
- A body's shape (about its centre; `scale` scales it, a number or `{ x, y, z }`):
  `box = { w, h, d }` (or one number for a cube), `sphere = r`, `capsule = { radius, height }`
  (or `{ radius, from, to }`), `cylinder = { radius, height, segments }`,
  `cone = { radius, height, segments }` (or `radius_bottom`, `radius_top`),
  `hull = { { x, y, z }, ... }` (convex), `mesh = { vertices = { x1, y1, z1, ... },
  indices = { 1, 2, 3, ... } }` (triangles; static bodies only), or `hull` / `mesh` naming a
  model of the media (`.glb`, `.gltf`, `.3mf`, `.obj`, `.usdz`, `.usdc`: its triangles), or
  `shapes = { { box = ..., position, rotation }, ... }` for one body of several shapes.
- The rest of a body is as in 2D, in 3D terms: `name`, `position`, `rotation`, `velocity`
  (`{ x, y, z }` m/s, or `vx`, `vy`, `vz`), `spin` (`{ x, y, z }` radians/s), `bounce`,
  `friction`, `rolling_resistance`, `density`, `gravity_scale`, `damping`, `spin_damping`,
  `bullet`; kinds `static`, `kinematic` with `move = function(t) return { x, y, z }, { rx, ry,
  rz } end`; `start`, `stop`, `asleep`, `leaves`, `layer`, `ignores`; and
  `lock_position` / `lock_rotation` (`true`, or `{ x, y, z }` booleans per axis: a body that
  only slides on a table, a door that only turns about Y).
- Joints, `{ kind, a = body, b = body, ... }` (a missing `a` or `b` is the world; joined
  bodies pass through each other unless `collide = true`): `"hinge"` (`at`, `axis` (default
  `{ 0, 0, 1 }`), `limit = { lo, hi }` radians, `motor =` radians/s with `torque`, `hertz` and
  `damping` for a spring), `"ball"` (`at`, `axis`, `cone` (radians: the swing about `axis`), `twist = { lo, hi }`
  (the turn around it), `motor = { x, y, z }` with `torque`; for a ragdoll, point `axis`
  along the limb at rest: `examples/physics3d_demo`'s Ragdoll), `"slider"` (`at`, `axis`, `limit = { lo, hi }` metres,
  `motor =` m/s with `force`), `"weld"` (`at`; `hertz`, `damping`, `angular_hertz`,
  `angular_damping` to make it give), `"rod"`, `"rope"`, `"spring"` (`from` on a, `to` on b,
  `length`; the spring's `hertz` 4, `damping` 0.5).
- Kicks: `{ t, body, velocity = { x, y, z }, spin = { x, y, z } }` add to its velocity at `t`.
- Thrusts: `{ from, to, body, acceleration = { x, y, z }, at = { x, y, z } }` push it from
  `from` to `to` with its mass times `acceleration` (m/s²) as a force at the point `at`, both
  in the body's own frame, so the push turns with it and, off its centre, turns it (Unity's
  AddForceAtPosition with ForceMode.Acceleration): thrusters, an engine, a hand on a door's
  edge. In space a start needs a stop: a push one way, then the same push back. A kick is an
  instant change of speed; a thrust is a burn.
- The result: `sim.bodies[i] = { name, settled, moving }`, `sim.names[name] = i`,
  `sim.contacts = { { t, a, b, position = { x, y, z }, normal, speed }, ... }` (also `x`, `y`,
  `z`; speed in m/s) for sounds on impacts, and `sim.tracks`, the poses kept natively.
- `physics3d_at(sim, body, t)` -> position, rotation (`physics_at` takes a 3D result too);
  `physics3d_instances(sim, t, bodies)` -> `{ { position, rotation }, ... }` for a mesh's
  `instances` (one draw for many bodies of one shape; without `bodies`: every body that is
  not static).
- `onimite show video.lua bodies` lists 3D bodies with the 2D ones (start and end positions in
  metres). Checks: `physics3d_overlap` (a body starts inside another), `physics3d_offscreen` (a
  body leaves the world's bounds for good), `physics_unsettled` (a frame samples past the end
  while a body still moves).

  `view3d_video_software`, `shader_depth_of` (a 2D shader's `depth_of` input), `shader_compile` (`Vertex:line:col` / `Fragment:line:col`, skipping the failed draw),
  `shader_undeclared_uniform`, `shader_unset_uniform`, `view3d_zero_size` and
  `view3d_render` (the renderer failed); see problems.md.
- `show video.lua nodes --at 2s` lists a `view3d` node like any other (`view3d of 5
  meshes, 1 model`); `show video.lua node/video.lua:28` shows its fields: the box, the
  camera, the environment, how many lights, meshes and models.
- `frame --svg` embeds the 3D box as a PNG at the size it shows.
- The 3D image is rendered at the box's size on screen (its groups' scale included), so it
  stays sharp; a full-HD box costs a full-HD 3D render per frame. On the CPU
  (`--software`) that is roughly as slow as a large shader; use the GPU for long renders.

## More examples

A product turntable: one model, a studio environment shown blurred behind it, the camera
still and the model turning:

```lua
view3d {
  camera = { fov = 30, position = { 0, 0.8, 5 }, target = { 0, 0.6, 0 } },
  environment = "studio.jpg", environment_intensity = 1.2,
  background = "studio.jpg", background_blurriness = 0.6, background_intensity = 0.5,
  models = { { src = "shoe.glb", rotation = { 0, f.seconds * 0.8, 0 }, scale = 3 } },
}
```

Bars of a 3D chart that grow (geometry fixed, `scale` animated; each bar stands on the
floor):

```lua
local values = { 3, 5, 2, 6 }
local meshes = {}
for i, v in ipairs(values) do
  local h = v * animate(f, { { start = 0.2 * i, stop = 0.2 * i + 0.8, from = 0, to = 1, easing = ease_out } })
  meshes[#meshes + 1] = { geometry = { type = "BoxGeometry" },      -- the unit box, every bar
    position = { (i - 2.5) * 1.4, h / 2, 0 }, scale = { 1, math.max(h, 0.001), 1 },
    material = { color = "#38bdf8", roughness = 0.5 }, cast_shadow = true }
end
meshes[#meshes + 1] = { geometry = { type = "PlaneGeometry", width = 12, height = 6 },
  rotation = { -math.pi / 2, 0, 0 }, material = { color = "#1e293b" }, receive_shadow = true }
view3d {
  x = 160, y = 120, w = 1600, h = 840,
  camera = { position = { 4, 6, 11 }, target = { 0, 2, 0 }, fov = 35 },
  lights = { { type = "AmbientLight", intensity = 0.6 },
    { type = "DirectionalLight", intensity = 2.5, position = { 3, 8, 5 }, cast_shadow = true,
      shadow = { map_size = 1024, height = 14, bias = -0.0005 } } },
  meshes = meshes,
}
```

An isometric look: an orthographic camera on the diagonal.

view3d {
